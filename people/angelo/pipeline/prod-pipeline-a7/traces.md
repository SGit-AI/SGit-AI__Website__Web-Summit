## How the tool works, and what it cannot see
`node people/angelo/pipeline/prod-pipeline-a7/tool/page-trace.mjs <Fringe clone> --out people/angelo/pipeline/prod-pipeline-a7/data` (Node 18, no dependencies, read-only git, about 5 s). Same clone head, same files: `traced_at` is the head commit's time.
- Event pages: every version of data/events.json is parsed; a commit that changed the entry (matched by id or source URL) is contributed, with the fields it changed; its `read_at`, `seen_at` and the ask in its body become interaction steps. data/organisers.json likewise for the organiser's entry. Then `git log -i -G<term>` over the whole repository for the id, the URL, the name and a short name (DISTRICT 909, stormsummit.app; not "Storm Summit", too common during Storm Charles); git lists only the files that matched; those outside the template are related.
- Pages with a builder: every commit to the page's own files (me.mjs, me.js, its inbox; tip.mjs, tip.js, its lanes, tips-status.json; home.mjs, event-images.json; programme.mjs); the work item that asked for it (work/26, work/41) as related; for the listings, every events.json commit with its added, changed and removed counts.
- **Cannot see:** deploy times (the Fringe's Actions, a gap); a person's words outside git unless a commit quotes them; sub-agents behind a commit; tip.mjs also holds the "give us the intel" box shown on other pages, so two of /tip/'s steps (00a6e45, 1608aef) may not have changed /tip/ itself; build.mjs's own home-page lines count as template.
