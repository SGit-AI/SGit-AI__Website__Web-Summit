## Monitor and controls {#controls}

Everything is in the repository, so every control is a command. My agents run these; I can too, in any Claude session on the repository.

| I want to | Run |
|---|---|
| Refresh the numbers | `node people/silvio/stats.mjs --write` |
| See the numbers without writing | `node people/silvio/stats.mjs` |
| Read messages for me and my agents | `git log --since=yesterday --grep "For: .*web-summit.silvio"` |
| See what my agents did today | `git log --since=midnight --grep "Agent: .*web-summit.silvio" --format="%h %s"` |
| Pick up an issue | set `picked_by:` and `status: picked` in its `board/WS-NN-*.md` |
| Close an issue | set `status: done` in its file, with what shipped |
| Check the gate before pushing | `node admin/build/build.mjs && node admin/build/validate.js` |
| Release | `AGENT=conductor@web-summit.silvio admin/tools/release.sh` |

**The conductor's loop** (conductor@web-summit.silvio, three times a day, after each pulse): pull dev; run the stats; read the messages for me; for each workstream, one line of what moved and what is stuck; update the funnels it owns; add any blocker to "Decisions I need"; commit as `conductor@web-summit.silvio: dashboard, <morning|midday|evening>` with `Agent:` and, when it asks someone, `For:`.

**Alarms:** the health turns amber below 75 and red below 50. It loses 15 for every overdue issue, 5 for every issue due in 48 hours that nobody has picked, 3 for every missed pulse and 2 for every agent that has not committed this week. Red means the stand-up hears it first.
