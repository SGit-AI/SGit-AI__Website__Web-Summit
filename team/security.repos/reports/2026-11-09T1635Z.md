### HIGH

1. **`promote.yml` assumes the default branch is `main`. PrompTugal__App__Android's default branch is `dev`.**
   - **Where:** PrompTugal/PrompTugal__App__Android, `.github/workflows/promote.yml` (from `888be5a`, rebuilt in `034b4ac`, `eee62bf`; on `dev`).
   - **What it does:** it holds the GitHub App key (`PROMOTE_APP_ID` and `PROMOTE_APP_PRIVATE_KEY`, in the Environment `promote`) that fast-forwards `main`. A push to `main` runs `play.yml`, which uploads to Google Play.
   - **Its stated safety:** the header says it runs "from the DEFAULT branch's copy of this file: someone who can push to dev cannot edit it to reach the App secrets". GitHub does run `workflow_run` (and `workflow_dispatch` on its default ref) from the **default branch**. Here that is `dev` (the clone's `HEAD`), which every agent and person on the team may push to. Anyone who pushes to `dev` can therefore change `promote.yml` itself: its trigger, its steps, and what it pushes to `main`.
   - **What stands between a push to `dev` and the App key:** only the Environment `promote`'s deployment-branch rule. The header says Dinis set it to "main only". I cannot read Environment settings from here (not checked).
     - **If the rule is "main only":** the `workflow_run` job runs on ref `dev`, so the Environment should refuse it. The App path then never runs and promotion always falls back to a pull request. That is safe but not what the flow intends.
     - **If the rule includes `dev`, or is unset:** the App key, and with it `main` and Play, is one push to `dev` away.
   - **Today:** `main` is still the initial commit ("not bootstrapped"). Until Dinis merges the release flow onto `main`, promotion only opens a pull request for a person. So this is a design defect to fix **before** that merge, not a live hole.
   - **Fix (for the owners to choose):**
     - (a) Make `main` the default branch, so the `workflow_run` and `pull_request_target` copies come from the protected branch, which is what the workflow's reasoning needs.
     - Or (b) keep `dev` as default and do not let a `dev`-triggered workflow hold the App key: promote by a person's merge, or from a workflow that is only ever triggered on `main`.
     - Either way, set the Environment `promote` to deployment branch `main` only, with a required reviewer, and check it in Settings.
   - **The same premise elsewhere:** `security-approval.yml` relies on `pull_request_target`, which runs from the pull request's *base* branch (`main`), so it is not affected. `play.yml` runs on a push to `main` and also guards `github.ref == 'refs/heads/main'`, so it is fine.
   - **Owners:** release.android@promptugal.ai.dinis and conductor.android@promptugal.ai.dinis. Dinis owns the default branch and Environment settings.
