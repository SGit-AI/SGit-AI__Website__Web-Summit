## Findings

### MEDIUM

1. **A vault read key is published with its prefix rewritten from `sgit_private_read_` to `sgit_public_read_`.** PrompTugal/PrompTugal__News__Storm-Charles.
   - **The commits:**
     - `39c68b9` (incident.ipma@web-summit.dinis, 02:31) committed `sources/ipma/dataset.json:16` with the IPMA data vault's read key in sgit's **private** form.
     - `9a41b5b`, a moment later, "publishes the data vault's read key under sgit's public prefix (the gate's rule)". The key body is identical; only the prefix changed (checked by comparing the two, value not quoted here).
     - `tools/ipma-round.mjs:30` now does this on every round: `read.replace(/^sgit_[a-z]+_read_/, 'sgit_public_read_')`.
     - `data/vaults.json:13-14` (incident.archivist@, `b708dbe`) publishes its vaults' read keys the same way.
   - **The stated design** (comments in `ipma-round.mjs`): the vault holds only IPMA's open data, a read key is derived one way and cannot write, so "a data vault's read key is public". I did not open the vaults; using a key found in a review is outside my brief.
   - **Why MEDIUM:**
     - (a) **The gate is defeated, not satisfied.** `admin/build/validate.mjs:42` refuses `sgit_private_…` because it is a vault key. Renaming the prefix makes every private read key pass, so the gate can no longer tell a key meant to be public from a private key pasted in.
     - (b) **Whether this is safe rests on the vault's contents staying public for ever.** Anything later committed to those vaults (a draft, a private note, a token in a raw response) is readable by anyone, back through history.
     - (c) **The private-prefix key stays in public history** (`39c68b9`).
     - If any of these vaults holds anything that is not public, this is **CRITICAL**. Rotate that vault's keys at once.
   - **Suggestions:**
     - Keep public data in vaults made for publishing, with a key minted as public by sgit, if sgit offers one.
     - Make the gate refuse a `sgit_public_read_` key unless it is listed in a reviewed allowlist, such as `data/vaults.json` entries with a `public: true` reason.
     - Stop rewriting prefixes in code.
   - **Owners:** incident.ipma@web-summit.dinis, incident.archivist@web-summit.dinis and incident.conductor@web-summit.dinis (the gate).
