### MEDIUM

1. **The App Store Connect API key in PrompTugal__App__iOS is a repository secret.** Every workflow on every branch can read it.
   - **Evidence:**
     - `.github/workflows/wallet-pass.yml` (`fd8ed90`, `eeb1f31`) has no `environment:`. Yet its run 3 used `ASC_KEY_ID`, `ASC_ISSUER_ID` and `ASC_KEY_P8_BASE64` to create a Pass Type certificate.
     - It then committed `briefs/2026-11-09__wallet-pass/card.pkpass` to `dev` as github-actions (`89f10f3`, 17:11).
     - So the key is not only in the `testflight` or `app-store` Environments that `ios-release.yml` and `ios-submit.yml` use.
   - **Why it matters:** an App Store Connect API key can upload builds, change the App Store event app's metadata and privacy answers, create certificates and submit for review. Anyone who can push any branch can add a `push:` workflow that reads it, and every agent can. That is the App Store line in content/apps.md, reachable in one push.
   - **Fix:**
     - Move the `ASC_*` secrets into Environments limited to protected branches, with a required reviewer.
     - Give `wallet-pass.yml` an Environment too.
     - Rotate the key after the move, since every branch could have read it until then.
   - **Owners:** conductor.B@ios.PrompTugal.dinis and Dinis (settings).
2. **The Android `release` Environment's secrets are reachable from `dev`'s own copy of `android.yml`.** PrompTugal__App__Android, `.github/workflows/android.yml:246-262`.
   - **What it holds:** the `release` job runs on every push to `dev` that changes the build, from `dev`'s copy of the file. It holds the Play upload keystore (`UPLOAD_KEYSTORE_*`), `id-token: write` for Google Workload Identity (Firebase App Distribution to testers), and `contents: write` for GitHub releases.
   - **Why it matters:** anyone who can push to `dev` can edit that job and take the upload key, or send testers a build of their own. `play.yml`'s provenance check would still refuse a release made outside this job for Google Play, and Play App Signing lets a lost upload key be reset, so the store itself is better protected than the testers.
   - **Correction:** my first run listed this as "used only in the release environment, on pushes to dev", which is true but is not a barrier.
   - **Fix:**
     - Give the Environment `release` a required reviewer, so a person approves each signing run.
     - Or sign and distribute only from `main`.
   - **Owners:** release.android@promptugal.ai.dinis and Dinis (settings).
