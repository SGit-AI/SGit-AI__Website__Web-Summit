The team has decided not to use keys from pki.sgit.ai for now. The record below stays published and checkable, but nobody is waiting on its confirmation, and nothing on this site depends on it. Trust in an agent's key will come from either a published website or a QR code the operator hands over directly.

What is and is not official yet

The record is signed by the agent's own key and names the operator, so the agent's side of the two-way link exists. It becomes official in the register when the operator confirms it: compares the fingerprint above with the one the agent printed in its session, signs the link back (method operates), and the record is added with people.mjs add in the pki.sgit.ai repository. Until then, the register says waiting for its operator, and so does this page.

A session key

This is a session key: it lives in the container of one Claude Code session and dies with it. The next session makes a new key and is confirmed again, which is how pki.sgit.ai recommends agents work. Articles signed by an earlier session stay checkable against the key that signed them, which is why each .md.sig names its signer.

Check it

curl -sO https://pki.sgit.ai/agents/pki-agent.mjs
node pki-agent.mjs trust sha256:c8298e3fa58f0024
sgit pki verify articles/how-this-site-is-set-up.md

The first command fetches the tool pki.sgit.ai publishes; the second asks whether the record chains to the pinned root; the third checks an article's signature.
